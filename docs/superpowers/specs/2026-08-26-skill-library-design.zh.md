# 技能库设置设计

[English](2026-08-26-skill-library-design.md) | 中文

## 范围

为 Web Profile 增加独立的“技能”设置项。保留现有的“插件”设置项不变：插件是可执行的运行时组件，技能是供 agent 使用的指令包及可选资源。

该设置项提供两种读取视图：

- “我的技能”列出 `${DSH_HOME:-~/.dsh}/skills` 中托管的用户技能，以及 `${DSH_HOME:-~/.dsh}/skills-disabled` 中本地保留的停用副本。
- “内置技能”列出由当前 Profile 的 bundled 或 runtime provider 提供的技能。该视图只读，且可能为空。产品不得把它描述为在线广场。

第一版将本地技能文件夹和 `.zip` 压缩包导入到用户根目录。项目本地技能根目录仅对其所在项目有效，不由此全局页面管理。远程或企业技能广场不在范围内。

## 用户体验

设置导航在“插件”旁增加“技能”。它包含“我的技能”和“内置技能”两个标签页。

“我的技能”提供“导入技能”按钮与可搜索的卡片列表。每张卡片显示 kebab-case 命令名、描述、来源路径、启用状态和资源摘要。用户可以查看技能指令、停用或启用技能，以及删除用户安装的技能。删除只移除 `~/.dsh/skills` 下的托管副本，绝不改动导入时选取的原始文件夹。

“内置技能”使用相同的可搜索卡片展示，但不提供修改操作。空状态说明当前 Profile 没有提供内置技能。

导入会打开一个对话框，提供两种输入：选择或拖入技能文件夹，或选择或拖入 `.zip` 压缩包。对话框先验证候选项，并显示名称、描述、入口文件、资源数量和所有可执行文件，之后才显示最终的“导入到我的技能”操作。同名导入绝不覆盖现有技能：对话框要求显式确认替换，否则用户取消。

成功导入后，对话框关闭，“我的技能”刷新，新卡片获得焦点。产品还会显示一条简短提示：在会话中输入 `/<name>`，选择对应建议，然后补充任务提示词。

## 调用

不构建第二套技能命令系统。Web Profile 已通过 `/` 输入来源公开每个用户可调用的技能。选择候选项会插入 `/<name> `；消息发送时，现有的 host pre-step handler 会加载其 `SKILL.md` 指令。

当这些 frontmatter 字段缺失时，导入技能默认采用 `user-invocable: true` 与 `model-invocable: true`，与 filesystem provider 保持一致。界面不得承诺一个显式设置 `user-invocable: false` 的技能可由斜杠菜单调用；其卡片应说明它无法从斜杠菜单使用。

## Host 设计

增加 host 侧 `skill-library` 插件。它拥有专用 remote API，而不扩展 `skill.list`，因为现有 API 有意只暴露按会话调用所需的数据，并隐藏 provider/来源细节。

该 API 包含四项操作：

- `list()` 返回用户根与内置条目，以及来源类别、路径、描述、调用策略和资源摘要。
- `inspect(name)` 返回已验证的 frontmatter 与供详情对话框使用的安全正文预览。
- `import(candidate, mode)` 验证文件夹或上传的压缩包，并将其原子安装到用户根目录；`mode` 为 `reject` 或显式的 `replace`。
- `setEnabled(name, enabled)` 与 `remove(name)` 只操作托管的用户根条目。

导入只接受恰含一个顶层技能 bundle 且其中含有 `SKILL.md` 的内容。它会拒绝路径穿越、解析后越出候选范围的符号链接、格式错误的 YAML、非 kebab-case 名称、重复 bundle，以及 bundle 外的压缩包条目。host 在临时目录中暂存解压内容并验证，随后将其重命名到安装位置。失败不得改变已有技能及其资源。

启用状态由位置表示，而不是编辑导入的 `SKILL.md`：停用时将 bundle 从 `~/.dsh/skills/<name>` 原子移动到 `~/.dsh/skills-disabled/<name>`，启用时反向移动。skill filesystem provider 继续拥有发现职责，因此把 bundle 移出其根目录即可让它从自动发现和斜杠菜单中消失，而不改变用户内容。

## Client 设计

增加 browser 侧 `ui-settings-skills` 插件。它贡献一个 id 为 `skills` 的 `settings.section` 项，复用已有 Settings section 契约，而不是在“插件”中增加标签页。它渲染两个标签页、导入对话框、卡片列表、空状态、无障碍焦点处理和中英文文案。

Profile 通过本地 bundle 安装 host 与 browser 两部分，方式可参照已有 Soho 定制。标准的“插件”设置项与 `ui-skill` 斜杠输入来源保持独立。

## 验证

测试覆盖 frontmatter 与压缩包验证、路径穿越和冲突拒绝、原子替换与回滚、启用/停用的可见性、只读内置条目以及来源区分和本地化标签。浏览器测试覆盖新的 Settings 入口、导入预览和确认、卡片操作、空状态，以及导入技能后的斜杠菜单发现。人工验收验证导入 `meeting-proposal`、选择 `/meeting-proposal`，并生成新的 Word 文件，且不改动内置的源模板。

## 不在范围内

本次发布不安装 npm 插件、不自动运行技能脚本、不获取远程技能包、不同步企业目录，也不改动现有插件清单。这些分别属于信任和分发功能。
